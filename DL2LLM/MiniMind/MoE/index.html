    稀疏混合专家网络 /MoE ¶

    • 核心思想 : 扩大模型参数量，但不增加单次推理的计算量 (FLOPs)。它将原本一个巨大的 FFN 分裂成了多个小的 FFN( 专家 )，每个 Token 根据内容只选择性地激活其中的一部分专家

    • 稀疏门控 (Sparse Gating)

      条件计算 (Conditional Computation): 对于每一个输入 Token，不让网络中所有的神经元都参与计算，而是通过路由只激活一小部分最擅长的来处理该 Token

      • 计算流程 :

        • 计算路由得分 (Routing Logits)。用一个线性层计算输入 \(x\) 对每个专家的原始匹配分数

          \[h(x) = x \cdot W_g\]

        • Top-K 选择 (Sparse Selection)。保留得分最高的 K 个专家，其余专家的权重全部置为 0

          \[KeepIndices = TopK(h(x), K)\]

        • 归一化权重 (Softmax)。对选中的 K 个得分进行 Softmax 归一化，得到门控权重，再与相应门控 FFN 输出相乘

    • 负载均衡 (Load Balancing)

      坍塌现象：路由器将绝大多数 Token 都交给某几个专家，其他专家从未激活

      • 产生原因 :
        • 初始化时，某些专家 A 的得分稍高一些
        • 专家 A 获得更多的 token 训练，梯度更新更频繁
        • 路由发现专家 A 效果更好，于是将更多 token 给它
        • 结果 : MoE 退化成 Dense 模型 ( 稠密的 FFN)

    • 辅助损失函数 (Auxiliary Loss)

      • 实际负载分布 (The Fraction Vector, \(f\))。一个 Batch 中，每个专家实际被选中的频率，这是一个离散的统计值，不可导，但可以用 mask 近似。

        \[f_i = \frac{1}{T}\sum_{t=1}^{T}1(Token \hspace{0.5em}t \hspace{0.5em}selected \hspace{0.5em}Expert \hspace{0.5em}i)\]

        其中 \(T\) 为 Batch 中的总 token 数

      • 门控概率分布 (The Probability Vector, \(P\))。门控网络选每个专家的平均概率，softmax 输出的平均值，平滑可导

        \[P_i = \frac{1}{T}\sum_{t=1}^{T}Softmax_i(h(x_t))\]

      以上两个都是 \(N\) 维的概率分布向量，目标是让 \(f\) 和 \(P\) 趋于均匀分布，由柯西 - 施瓦茨不等式，最小化两个向量的点积可以使它们均匀

      \[L_aux = \alpha N \cdot \sum_{i=1}^{N}(f_i \cdot P_i)\]

      其中 \(\alpha\) 为超参数，取 0.01/0.001，\(N\) 为专家数量，乘 N 目的是让 Loss 的量级不随专家数量变化 ( 点积越小 == 负载越均衡 )

    • Shared Experts ( 共享专家 )

      • 针对问题 : 所有专家都要经过路由选择，导致模型很难学到通用知识，每个专家都要重复学一遍这些通用知识。浪费参数，训练不稳定

      • 核心思想 : 专家分为两类。

        • 共享专家 (Shared experts)。不参与竞争，总是被激活，负责拟合数据的均值或者通用知识
        • 路由专家 (Routed Experts)。参与 Top-K 竞争，负责拟合数据的残差或者特定领域的专业知识

      • 公式 :

        \[ y = \underbrace{\sum_{j=1}^{N_shared}E_j^{shared}(x) }_{Fixed\hspace{0.5em}Path(通用知识)} + \underbrace{\sum_{i \in TopK}g_i(x) \cdot E_i^{routed}(x)}_{Conditional \hspace{0.5em}Path(专业知识)} \]

      • 优势 :

        • 梯度高速公路 (Gradient Highway)。无论路由器怎么随机初始化，共享专家都能提供稳定的梯度回传，利于训练初期的稳定
        • 知识解耦。让路由专家学习 " 长尾知识 "，不用学习通用知识
        • 负载均衡。共享专家不参与负载均衡损失计算 ( 总是参与计算 )，减小路由压力，加快收敛

    • 代码实现 : 

      class MOEFeedForward(nn.Module):
    def __init__(self, config: MiniMindConfig):
        super().__init__()
        self.config = config
        # 路由机制，输出是专家总数
        self.gate = nn.Linear(config.hidden_size, config.num_experts, bias=False)
        # 每个专家都是一个SwiGLU门控FFN
        self.experts = nn.ModuleList([FeedForward(config, intermediate_size=config.moe_intermediate_size) for _ in range(config.num_experts)])
        self.act_fn = ACT2FN[config.hidden_act]

    def forward(self, x):
        batch_size, seq_len, hidden_dim = x.shape
        # -1:自动计算维度 [batch_size * seq_len, hidden_dim]
        x_flat = x.view(-1, hidden_dim)

        # 1. 计算路由得分 [batch, seq, num_experts]
        scores = F.softmax(self.gate(x_flat), dim=-1)

        # 2. Top-K选择
        # topk_weight: 选择专家的softmax分数，topk_idx: 选择的专家索引
        topk_weight, topk_idx = torch.topk(scores, k=self.config.num_experts_per_tok, dim=-1, sorted=False)
        if self.config.norm_topk_prob: 
            topk_weight = topk_weight / (topk_weight.sum(dim=-1, keepdim=True) + 1e-20)

        # 3. 专家计算
        y = torch.zeros_like(x_flat)
        for i, expert in enumerate(self.experts):
            # 找出当前被分配给该专家的所有 Token 的索引
            mask = (topk_idx == i)
            if mask.any():
                # 让这个专家只处理挑出的这些 Token，并将输出乘上路由权重
                # 把不同专家算出来的结果加回最终总张量 y 中对应的位置
                token_idx = mask.any(dim=-1).nonzero().flatten()
                weight = topk_weight[mask].view(-1, 1)
                y.index_add_(0, token_idx, (expert(x_flat[token_idx]) * weight).to(y.dtype))
            elif self.training:
                y[0, 0] += 0 * sum(p.sum() for p in expert.parameters())
        if self.training and self.config.router_aux_loss_coef > 0:
            # 负载均衡损失(Load Balancing Loss)，使路由器把 Token 均匀地派给所有的专家
            # load: 每个专家实际被选中的概率
            # scores.mean(0): 门控网络分配给每个专家的概率
            load = F.one_hot(topk_idx, self.config.num_experts).float().mean(0)
            self.aux_loss = (load * scores.mean(0)).sum() * self.config.num_experts * self.config.router_aux_loss_coef
        else:
            self.aux_loss = scores.new_zeros(1).squeeze()
        return y.view(batch_size, seq_len, hidden_dim)
      如果训练时有些专家一个词都没分到，代码有个小 fallback 加一个0的梯度保证不出错。
