    Attention/ 注意力机制 ¶

    一种让模型学会 " 关注 " 的机制，让模型能 " 查看 " 所有上下文，自动学会关注重要的信息，并且忽略不相关的信息 类比在图书馆找书 Query（查询）：想找什么内容的书 Key（索引）：每本书的关键词 Value（内容）：书的实际内容 Attention：根据查询和索引的匹配度，决定选择哪本书 公式: \(\(\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V\)\) 计算流程: 1. 计算相关性：Query 和 Key 的点积 

    Q: [batch, seq_len, d_k]
K: [batch, seq_len, d_k]
->
QK^T: [batch, seq_len, seq_len]
每两个 token 之间的相关性
    seq_len × seq_len 的矩阵，第 (i, j) 个元素表示 token_i 和 token_j 的相关性。 2. 归一化：softmax 转为概率分布 softmax将分数转为概率分布，所有位置的权重加起来 = 1 \(\(\text{softmax}(x_i) = \frac{e^{x_i}}{\sum_j e^{x_j}}\)\) 3. 加权求和：用概率分布对 Value。 attention_weights: [batch, seq_len, seq_len] * V: [batch, seq_len, d_v] -> output: [batch, seq_len, d_v] 每个 token 的输出是所有 Value 的加权平均，权重由相关性决定
    • 为什么 Q、K、V 为什么要分开？ 这样可以学习"我想要什么"和"我有什么"的不同表示
    • 如果去掉 Attention，只用 FeedForward 会怎么样？ 这样模型无法看到上下文，只能逐词处理

    Attention¶

    • self-Attention 自己看自己，句子中的词互相看，不看外部信息 Q、K、V 都来自同一个输入,三个投影矩阵W是可学习参数 
      # 输入 x: [batch, seq_len, hidden_dim]
Q = x @ W_Q  # [batch, seq_len, d_k]
K = x @ W_K  # [batch, seq_len, d_k]
V = x @ W_V  # [batch, seq_len, d_v]
    • Multi-Head Attention 多个头并行，每个头来学不同模式，单个头只能学一种关系模式 性质: 参数多，计算慢，但效果最好 例子: 不同头学到的模式
      • Head 1：语法关系（主谓宾）
      • Head 2：语义相似（同义词）
      • Head 3：位置关系（相邻词）
      • Head 4：代词指代关系

    • MQA (Multi-Query Attention) 所有Q头共享一个 KV 性质: 参数少，推理快，但效果稍差

    • GQA(Grouped Query Attention) 

      MHA 的问题：KV Cache 太大
MHA: 每个头独立的 K、V
8 heads × 512 seq × 64 dim = 262,144 参数/token
      多个 Q 头共享 KV 作用: 平衡效果和效率，精度几乎不损失，但内存和速度显著提升。减少KV Cache内存，加速推理 
      MiniMind:
8 个 Q 头，2 个 KV 头,每 4 个 Q 共享一组 KV
内存减少 75%

    • Flash Attention 不存储完整 attention 矩阵,内存效率更高;融合操作,速度更快 标准实现的问题：需要物化整个 attention 矩阵 (seq_len × seq_len);频繁读写 GPU HBM（慢） 作用: 减少GPU内存访问，加速计算

      • 分块计算，充分利用 SRAM（快）
      • 不物化完整的 attention 矩阵
      • IO 访问减少，速度提升 2-4 倍
      • 支持更长序列 , 内存占用从 O(N²) 降到 O(N)

      • 0：允许注意
      • \(-\infty\)：禁止注意 ,softmax 后 = 0

    • 代码实现 
      class Attention(nn.Module):
    def __init__(self, config: MiniMindConfig):
        super().__init__()
        self.n_heads = config.num_attention_heads       # 8
        self.n_kv_heads = config.num_key_value_heads   # 2 (GQA)
        self.head_dim = config.hidden_size // self.n_heads  # 64
        self.n_rep = self.n_heads // self.n_kv_heads   # 4

        # QKV 投影
        self.wq = nn.Linear(config.hidden_size, self.n_heads * self.head_dim, bias=False)
        self.wk = nn.Linear(config.hidden_size, self.n_kv_heads * self.head_dim, bias=False)
        self.wv = nn.Linear(config.hidden_size, self.n_kv_heads * self.head_dim, bias=False)
        self.wo = nn.Linear(self.n_heads * self.head_dim, config.hidden_size, bias=False)

    def forward(self, x, pos_ids, mask):
        batch, seq_len, _ = x.shape

        # 1. 计算 Q, K, V
        xq = self.wq(x).view(batch, seq_len, self.n_heads, self.head_dim)
        xk = self.wk(x).view(batch, seq_len, self.n_kv_heads, self.head_dim)
        xv = self.wv(x).view(batch, seq_len, self.n_kv_heads, self.head_dim)

        # 2. 应用 RoPE
        xq, xk = apply_rotary_emb(xq, xk, self.freqs_cis[pos_ids])

        # 3. GQA：扩展 KV 以匹配 Q 的头数
        xk = repeat_kv(xk, self.n_rep)  # [batch, seq, n_heads, head_dim]
        xv = repeat_kv(xv, self.n_rep)

        # 4. 转置以便矩阵乘法
        xq = xq.transpose(1, 2)  # [batch, n_heads, seq, head_dim]
        xk = xk.transpose(1, 2)
        xv = xv.transpose(1, 2)

        # 5. 计算注意力分数
        scores = torch.matmul(xq, xk.transpose(-2, -1)) / math.sqrt(self.head_dim)

        # 6. 应用因果掩码
        if mask is not None:
            scores = scores + mask

        # 7. Softmax
        attn_weights = F.softmax(scores, dim=-1)

        # 8. 加权求和
        output = torch.matmul(attn_weights, xv)

        # 9. 合并头 + 输出投影
        output = output.transpose(1, 2).contiguous().view(batch, seq_len, -1)
        return self.wo(output)
# GQA：repeat_kv 函数
def repeat_kv(x: torch.Tensor, n_rep: int) -> torch.Tensor:
    """
    将 KV 头扩展以匹配 Q 头数
    复制不占额外内存，只是改变视图

    每个 KV 头复制 4 次
    [batch, seq, 2, 64]（2 个 KV 头）  *
    n_rep = 4
    ->
    [batch, seq, 8, 64]（8 个头，匹配 Q）
    """
    if n_rep == 1:
        return x

    batch, seq_len, n_kv_heads, head_dim = x.shape

    # [batch, seq, n_kv_heads, 1, head_dim]
    x = x[:, :, :, None, :]

    # 扩展并重塑
    x = x.expand(batch, seq_len, n_kv_heads, n_rep, head_dim)
    return x.reshape(batch, seq_len, n_kv_heads * n_rep, head_dim)

    Q&A¶

    1. 为什么要缩放？除以 \(/ \sqrt{d_k}\) 因为点积的方差(点积的期望方差 = \(d_k\))随 \(d_k\) 增大而增大，大数值会让 softmax 饱和(梯度接近 0)，而除以 \(\sqrt{d_k}\) 可以稳定方差，防止梯度消失/爆炸 Softmax高分数对应高权重。Attention 分数很大，Softmax 后会变成接近 [0, 0, ..., 1]的权重，几乎只关注一个词

    2. attention 中 contiguous() 的作用？ transpose 不改变内存布局，只改变视图，view 需要连续内存，contiguous会重新排列内存 PyTorch tensor 有两个概念：

      • 存储（Storage）：实际的内存布局
      • 视图（View）：如何解释这块内存

      transpose： 

      # 假设 output 形状是 [batch, n_heads, seq, head_dim]
# 内存布局是按这个顺序排列的
output = output.transpose(1, 2)
# 现在形状是 [batch, seq, n_heads, head_dim]
# 但内存布局没变！只是改变了"视图"
      view() 要求 tensor 在内存中是连续的，但 transpose 后内存不连续： 
      # 原始内存顺序（简化示例）：
# [head0_pos0, head0_pos1, head1_pos0, head1_pos1, ...]
# transpose 后逻辑顺序：
# [head0_pos0, head1_pos0, head0_pos1, head1_pos1, ...]

# 内存不连续 → view 会报错
      contiguous 
      output = output.transpose(1, 2).contiguous()
# 1. 重新分配内存
# 2. 按新的逻辑顺序排列数据
# 3. 现在可以安全使用 view
      contiguous() 需要拷贝内存，有开销，但这是必要的开销 替代方案： reshape() 会自动处理，但不够显式 
      # 明确知道需要连续内存时，显式调用
output = output.transpose(1, 2).contiguous().view(...)
# 或使用 reshape（隐式处理）
output = output.transpose(1, 2).reshape(...)
      3. 假设你在调试一个 Attention 模块，发现所有 token 的注意力权重几乎均匀分布（每个位置都是 \(\approx\)1/seq_len），这可能是什么问题？如何解决？ 可能的问题： - Q 和 K 没有正确初始化 投影矩阵初始值太小，导致 Q·K 分数接近 0，softmax(0, 0, ..., 0) ≈ 均匀分布 - 缩放因子问题 除以了过大的值或忘记开根号(除以 \(d_k\) 而不是 \(\sqrt{d_k}\) - head_dim 设置错误 head_dim 过大导致点积方差过大,但这通常会导致极端分布，不是均匀分布 - 没有学习到有意义的模式 训练数据问题,或者模型容量不足

      解决方案 : - 检查 Q·K 分数

print(f"scores mean: {scores.mean()}, std: {scores.std()}")

      4. 为什么Self-Attention 中 Q、K、V 都来自同一个输入 x，但还需要三个不同的投影矩阵？直接用 x 做 Q、K、V 不行吗？ 直接用x相当于计算每个 token 与其他 token 的"余弦相似度"(内积)。 - token_i 对 token_j 的注意力 = token_j 对 token_i 的注意力，但语言中关系往往是不对称的。比如"猫吃鱼"：猫应该注意鱼，但鱼不一定要注意猫 - 表达能力有限，只能表达"相似度"这一种关系，无法学习"主谓关系"、"修饰关系"等

      三个投影矩阵可以让模型学习 " 从什么角度看待这个 token"；Q：作为查询时应该关注什么特征？，K：作为被查询时应该展示什么特征，V：实际应该传递什么内容 作用: - 非对称性：Q 和 K 不同，允许非对称关系 - 角色分离：查询角度、被查询角度、内容传递可以不同 - 表达能力：可以学习任意复杂的关系模式
