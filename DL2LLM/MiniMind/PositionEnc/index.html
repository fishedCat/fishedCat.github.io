    Position Encoding/ 位置编码 ¶

    self-attention 本身是排列不变的 (permutation invariant), 需要额外信息来区分顺序

    如果没有位置编码，两个句子包含相同的词 ( 集合相同 )( 如：你喜欢我，我喜欢你 )，那么 Attention 权重完全相同，无法区分顺序。但是两个句子的语义完全不同。即对于序列中的每一个 token，其他各个位置对其来说都是平等的，即“我喜欢你”和“你喜欢我”在注意力机制看来是完全相同的

    RoPE¶

    • 核心思想 : 用旋转角度编码位置，通过旋转向量来表示不同位置。位置 i 的向量旋转 i×θ 度，相对位置 = 相对旋转角度
    • RoPE 同时包含绝对和相对位置信息

    • 公式 : 对于向量 \(\mathbf{x} = [x_0, x_1, ..., x_{d-1}]\)，位置 \(m\) 的 RoPE 变换：

      \[\text{RoPE}(\mathbf{x}, m) = \begin{bmatrix} \cos(m\theta_0) & -\sin(m\theta_0) & & & \\ \sin(m\theta_0) & \cos(m\theta_0) & & & \\ & & \cos(m\theta_1) & -\sin(m\theta_1) & \\ & & \sin(m\theta_1) & \cos(m\theta_1) & \\ & & & & \ddots \end{bmatrix} \begin{bmatrix} x_0 \\ x_1 \\ x_2 \\ x_3 \\ \vdots \end{bmatrix}\]

      其中，每两个维度配对，使用同一个旋转矩阵；不同维度对使用不同的频率 \(\theta\)。

    • 频率的公式为 $$ \theta_i = \frac{1}{\text{base}^{2i/d}} $$ 其中：

      • \(\text{base} = 10000\)（标准）或 \(1000000\)（MiniMind）
      • \(d\)：头维度（head_dim）
      • \(i = 0, 1, 2, ..., d/2-1\)

      MiniMind 中 head_dim=64 

      rope_base = 1000000.0  # 更大的base → 更好的长度外推能力
freqs = [1/1000000^(2i/64) for i in range(32)]
      • 代码中生成了 32 种不同频率 \(\theta_0,...,\theta_{31}\)
        • 高频（i=0）：\(\theta_0 = 1.0\)，RoPE 中每 \(2\pi\) 转一圈（约 6 个 token）
        • 中频（i=15）：\(\theta_{15} = 0.001\)，RoPE 中每 6283 个 token 转一圈
        • 低频（i=31）：\(\theta_{31} = 0.000001\)，RoPE 中每 628 万 个 token 转一圈

    • 多种频率的作用 :

      • 频率对应的 RoPE 为 : 高频 -> 局部位置 ; 中频 -> 中等距离 ; 低频 -> 全局位置

      • 不使用一种频率的原因 :

        • 只用高频：长序列时 " 转了很多圈 "，位置信息模糊
        • 只用低频：短序列时 " 转得太慢 "，位置区分度不够，模型很难区分相邻的位置；浮点数精度不够，无法表示这么小的差别

      • 使用多频率的原因 :

        • 高频：区分相邻 token（如词内的字）
        • 低频：区分远距离 token（如段落之间）
        • 组合起来：可以唯一标识百万级位置

    • 相对位置信息

      • 核心思想 : RoPE 编码后的点积只依赖相对位置

      • 点积 :

        \[\mathbf{q}_m \cdot \mathbf{k}_n = f(\mathbf{q}, \mathbf{k}, m-n)\]

        其中，m、n 是绝对位置，\(q_m\) 为位置 m 的 Query，\(k_n\) 为位置 n 的 Key。可以看出点积只与 \(m-n\) 有关

    • 长度外推能力 (YaRN)

      • 推理时处理的序列长度比训练时的序列长度都要大
      • RoPE 可以外推，只需要旋转更多的角度，绝对位置编码无法外推
      • YaRN 算法作用 :
        • 动态调整旋转频率
        • 让模型更好地适应超长序列

    • RoPE 的作用 :

      • 自然包含相对位置信息与绝对位置信息。绝对位置信息 : 每个词编码了自己的位置，不同维度组合唯一标识位置；相对位置信息 : Attention 分数只依赖相对距离
      • 计算高效（预计算 cos/sin）
      • 支持长度外推 (YaRN)( 训练短序列，推理长序列 ), 相比绝对位置编码的主要优势

    • 代码实现 : 

      def compute_freqs(head_dim: int, seq: int, rope_base: float = 1e6, rope_scaling=None):
    """
    预计算 RoPE 的旋转矩阵
    seq: max_position_embeddings, 即模型最多能处理多长的句子，MiniMind中是32768个token
    max_position_embeddings: 模型最多能处理多长的句子,大模型的上下文窗口(context window)
    hidden_dim: 每个词/token的向量维度大小 
    """

    '''
    torch.arange(0, head_dim, 2)：生成 [0, 2, 4, ..., head_dim-2]
    [: (head_dim // 2)]：取前 head_dim/2 个（因为两两配对,//是整除）
    / head_dim：归一化到 [0, 1)
    '''
    # 计算频率θ:1 / (base^(2i/dim))，i = 0, 1, 2, ..., d/2-1
    freqs = 1.0 / (rope_base ** (torch.arange(0, head_dim, 2)[: (head_dim // 2)].float() / head_dim))
    # 生成位置m的序列 [0, 1, 2, ..., seq-1]
    t = torch.arange(seq, device=freqs.device, dtype=torch.float32)

    # YaRN 长度外推（可选）
    if rope_scaling is not None:
        t = t / rope_scaling

    # 计算每个位置的旋转角度mθ：位置 * 频率(外积计算，每个位置与每个频率相乘得到一个矩阵)
    freqs = torch.outer(t, freqs)  # [seq, head_dim//2]
    ''' 
    复数乘法 = 旋转,向量x * freqs_cis = 旋转后的向量x
    转换为复数形式(cosθ + i*sinθ)
    torch.polar(abs, angle),复数 = abs * ( cos(angle) + i*sin(angle) ),其中abs是模长，angle是角度
    torch.ones_like(freqs)，生成和 freqs 形状一样的全1张量，即模长为1
    '''
    freqs_cis = torch.polar(torch.ones_like(freqs), freqs)  # [seq, head_dim//2]

    return freqs_cis
def apply_rotary_emb(Q: torch.Tensor, K: torch.Tensor, freqs_cis: torch.Tensor):
    """将 RoPE 应用到 Query 和 Key"""

    # 将实数向量转为复数
    # [batch, seq, heads, head_dim] -> [batch, seq, heads, head_dim//2, 2]
    # Q.shape[:-1]取除了最后一维之外的所有维度,最后一维拆成两维：(-1, 2)，每组 2 个元素，自动算多少组
    # 加 * 就是把元组拆成一个个独立数字，即把括号拆掉
    Q_ = torch.view_as_complex(Q.float().reshape(*Q.shape[:-1], -1, 2))
    K_ = torch.view_as_complex(K.float().reshape(*K.shape[:-1], -1, 2))

    # 调整 freqs_cis 形状以便广播
    freqs_cis = freqs_cis[:, None, :]  # [seq, 1, head_dim//2]

    # 复数乘法 = 旋转
    # 广播机制: freq没有B这一维 -> 自动补1 -> 补到B维
    # 把复数转回实数，[B, seq, heads, D] → [B, seq, heads, D, 2]
    # .flatten(3)把最后两维压平，恢复成正常向量，[..., D, 2] → [..., D*2]
    Q_out = torch.view_as_real(Q_ * freqs_cis).flatten(3)
    K_out = torch.view_as_real(K_ * freqs_cis).flatten(3)

    return Q_out.type_as(Q), K_out.type_as(K)
class Attention(nn.Module):
    def __init__():
        pass
    def forward(self, x, pos, mask):

        batch, seq_len, _ = x.shape
        Q = self.w_q(x)
        K = self.w_k(x)
        V = self.w_v(x)

        Q = Q.view(batch, seq_len, self.num_heads, self.head_dim)
        K = K.view(batch, seq_len, self.num_heads, self.head_dim)
        V = V.view(batch, seq_len, self.num_heads, self.head_dim)

        # ⭐ 应用 RoPE（只对 Q 和 K）
        Q, K = apply_rotary_emb(Q, K, self.freqs_cis[pos])

        # 计算注意力分数
        attn_scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(self.head_dim)
        pass

    • 为什么代码中要用复数表示旋转？

      因为复数形式更简洁、更快 , 而且和矩阵写法的效果是一样的 复数乘法天然表示 2D 旋转，

      \[e^{i\theta} = \cos\theta + i\sin\theta \\ (a + bi) \times e^{i\theta} = (a\cos\theta - b\sin\theta) + i(a\sin\theta + b\cos\theta)\]

      换成矩阵写法的话就是 ,

      \[\begin{bmatrix} \cos(\theta) & -\sin(\theta)\\ \sin(\theta) & \cos(\theta)\\ \end{bmatrix} \begin{bmatrix} a \\ b \end{bmatrix}\]

    • 为什么 head 中要两两配对？[..., head_dim] → [..., head_dim//2, 2]

      因为 2D 旋转需要两个坐标。每两个维度组成一对，应用同一个旋转角度，head_dim=64 → 32 对 → 32 个不同频率 - 为什么要保持数据类型? Q_out.type_as(Q)

      复数运算需要 float32，但模型可能用 BF16/FP16，转回原始类型保持一致

    Q&A¶

    1. 为什么 RoPE 只旋转 Q 和 K，不旋转 V？

      因为位置信息只需要影响 " 匹配度 "(Q·K)，不需要影响 " 内容 "(V)，位置信息已经通过 Q·K 的点积融入了

    2. 具体的 RoPE 实例是什么样的？

      针对每个位置向量 \(\mathbf{x} = [x_0, x_1, ..., x_{d-1}]\)，以前四个维度为例

      • 纵向看 - 沿 位置 维度 :

        • 维度 0(\(x_0\), 高频 ): 随位置增加，角度变化快
        • 维度 3(\(x_3\), 低频 ): 随位置增加，角度变化相对较慢

      • 横向看 - 沿 嵌入 维度 :

        • 从维度 0 到维度 3: 频率递减，转动速度逐渐变慢 , 观察同一位置 ( 表格同一行 ), 从维度 0 到维度 3，频率递减导致累计旋转圈数也递减
        • 维度 0 每 6.3 个 token 转一圈 , 维度 3 约每 23 个 token 转一圈（约 4 倍慢）

      • 不同维度组合 → 唯一标识每个位置

    3. 为什么不需要反向旋转？/ 为什么只需要向一个方向旋转就行了？

      RoPE 的目标是区分不同位置，只要每个位置的角度不同就行，而顺时针和逆时针都能做到这一点，所以选一个方向就够了，不需要双向

    4. 为什么不用一个超低频率覆盖所有位置？

      • 浮点数精度限制 :

        float32 只有 6-7 位有效数字 , 超低频率的相邻位置差别 < 精度下限 , 无法在计算机中表示和区分

      • 信噪比太低 :

        相邻位置的角度差太小（微弧度）,Attention 分数几乎相同 , 模型失去位置区分能力

      • 多频率的优势 :

        • 高频：区分相邻位置（1, 2, 3...）
        • 低频：覆盖长距离（1000, 10000...）
        • 组合：每个位置有唯一且可区分的 " 编码 "

    5. 性能改进方法

      内存 : 

      # 好：预计算并存储
self.register_buffer('freqs_cis', precompute_freqs_cis(...))

# 差：每次 forward 计算
freqs_cis = precompute_freqs_cis(...)  # 浪费计算
      计算: 
      复数乘法比矩阵乘法快：
矩阵：4 次乘法 + 2 次加法
复数：2 次乘法 + 2 次加法（利用 GPU 优化）

    6. 假设你训练了一个 RoPE 模型，max_seq_len=512。现在需要处理 2048 长度的文本，可能会遇到什么问题？如何解决？

      可能的问题：

      • 性能下降： 虽然数学上可以外推，但模型没见过这么长的序列，长距离的注意力模式可能不准确
      • 旋转角度过大： 位置 2000 的旋转角度是训练时的 4 倍，高频维度可能"转太多圈"，信息丢失

      解决方案：

      • 使用 YaRN( 推荐 )： 动态调整旋转频率,让长序列的旋转更"缓和" 
        # 在 MiniMind 中启用
config.inference_rope_scaling = True
      • Position Interpolation( 位置插值 )： 简单但有效,相当于"压缩"位置范围 m(位置) * L_train(预训练最大长度) / L_infer(推理目标长度) 
        # 将位置缩放到训练范围内
pos_ids = pos_ids * (512 / 2048)
      • 继续训练： 用长序列数据微调模型,让模型适应长距离注意力
      • 训练时尽量用大的 rope_base（如 1e6）

    7. 为什么 RoPE 的点积只依赖相对位置 ? 数学原理

      假设：

      • 位置 m 的 Query：\(q_m = R(m\theta) \cdot q\)（旋转 mθ 角度）
      • 位置 n 的 Key：\(k_n = R(n\theta) \cdot k\)（旋转 nθ 角度）

      点积：

      \[q_m \cdot k_n = [R(m\theta) \cdot q] \cdot [R(n\theta) \cdot k]\]

      由于旋转矩阵的转置等于逆旋转

      \[= q \cdot R(-m\theta) \cdot R(n\theta) \cdot k \\ = q \cdot R((n-m)\theta) \cdot k\]

      所以点积只包含 \((n-m)\theta\)，即相对距离，不包含绝对位置 \(m\) 或 \(n\)
