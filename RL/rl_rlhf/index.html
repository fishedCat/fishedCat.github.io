    强化学习 - RLHF ¶

    约 2691 个字 预计阅读时间 9 分钟

    本篇为强化学习系列第 8 篇：LLM 强化学习前沿——RLHF( 基于人类反馈的强化学习 )

    承接上一篇：PPO 已经给出了稳定的策略梯度框架，适合大模型微调；但普通 RL 需要环境奖励，而大语言模型没有天然奖励函数。RLHF 的核心思路：先用人类偏好训练奖励模型，再以奖励模型作为环境，用 PPO 微调大模型，让模型输出对齐人类偏好。

    前置回顾 ¶

    • PPO 是近似 on-policy 的策略梯度算法，依靠 clip 约束重要性权重，避免策略漂移，一阶优化、工程友好，是 RLHF 的基础算法
    • 普通强化学习：状态 \(s\)、动作 \(a\)、环境给出标量奖励 \(r\)；
    • LLM 场景的特殊性：
    • 状态 \(s\)：prompt + 已经生成的上下文 \(y_{<t}\)
    • 动作 \(a\)：下一个生成 token \(y_t\)
    • 没有环境自动给出的奖励，人类只能对比两个回答，给出偏好（A 更好 / B 更好），很难直接打分
    • 动作空间巨大：词表上万，序列生成是长序列决策，原始奖励只在序列末尾稀疏给出
    • RLHF 三步走：SFT 监督微调 → RM 奖励模型训练 → PPO 强化学习对齐
    • 前置关键：PPO-ptx，在 RL 阶段加入预训练 loss，防止模型“遗忘基础能力”，也就是模型坍缩 / 对齐税

    RLHF 不是一个单独算法，是一套流水线：用人类偏好构造奖励，把大语言模型变成强化学习里的策略 \(\pi_\theta\)，用 PPO 做策略优化。 PPO之所以成为LLM对齐的主力，是因为它的Clip目标可以逐 token地施加信任区域，而不需要对整个序列概率做复杂约束。

    1. RLHF 整体流程（InstructGPT 原版三步）¶

    1.1 Stage1：SFT 监督微调（Supervised Fine-Tuning）¶

    目标：把基座模型从“补全文本”改成遵循指令的模型，教会模型看懂 prompt、输出规范回答。

    • 数据：人工标注的 (prompt, 高质量回答) 指令对
    • 训练方式：标准语言建模（自回归），最大化标注回答的对数似然 $$ \mathcal{L}{\text{SFT}} = -\sum) $$}\log\pi_{\text{SFT}}(a_t|\text{prompt},a_{1:t-1
    • 输出：SFT 模型 \(\pi^{\text{SFT}}\)，这是后续 RM、PPO 的起点，同时作为 RL 阶段的参考模型 \(\pi_{\text{ref}}\) 冻结使用
    • 局限： 1. 高质量标注成本极高，标注量有限 2. 只能学到标注样本的风格，无法覆盖所有人类偏好 3. 监督学习只能拟合标注，不能泛化到“更符合人类喜好”的未见过的回答

    SFT 是保底底座：没有 SFT，直接做 RL，模型不知道怎么生成通顺、符合指令的文本，RL 很容易跑到无意义输出。

    1.2 Stage2：RM 奖励模型训练（Reward Model）¶

    目标：从成对人类偏好学习一个打分函数 \(R(x,y)\)，输入 prompt+ 完整回答，输出一个标量奖励，替代人类实时打分。

    • 数据构造：同一个 prompt，给 SFT 模型生成多个候选回答，交给标注员对比排序 输入：\(x=\text{prompt}\)，两个回答 \(y_w\)（差回答）、\(y_l\)（好回答） 标注：\(y_l \succ y_w\)（人类偏好y_l）
    • 模型结构：一般复用 SFT 模型主干，最后一层加一个单独输出头，输出标量奖励 \(r=R_\psi(x,y)\)
    • 损失函数（排序损失，pairwise loss） $$ \mathcal{L}{\text{RM}} = -\log\sigma\big(R\psi(x,y_l)-R_\psi(x,y_w)\big) $$ \(\sigma\) 是sigmoid函数：希望偏好回答的奖励显著高于不偏好的回答。
    • 要点：
    • RM 只学习相对偏好，不需要绝对分数，只需要区分好坏
    • 训练完成后，RM 固定不动，作为 PPO 阶段的“静态奖励打分器”
    • RM 输出是全局序列奖励：一个完整回答结束才输出一个标量，不是每个 token 单独奖励
    • RM 的缺陷：RM 会有奖励黑客（reward hacking），模型学会欺骗 RM，拿到高分但人类不喜欢

    一句话：人类不会给每个回答直接打分，只会对比；奖励模型就是把成对偏好，变成一个可微分、可给 RL 用的奖励函数。

    1.3 Stage3：PPO 强化学习对齐（核心 RL 阶段）¶

    目标：以 SFT 模型为初始策略，以 RM 为奖励，用 PPO 微调策略模型，最大化人类偏好奖励，同时约束模型不要离参考模型太远。

    1.3.1 RLHF 里的四个核心模型 ¶

    角色 符号 作用
    Actor（策略） \(\pi_\theta(y_t\mid x,y_{<t})\) 被训练的语言模型，执行 token 生成，是我们要优化的目标
    Critic（价值） \(V_\phi(x,y_{\le t})\) 通常和 Actor 共享主干，加标量输出头；估计每个生成前缀 \(x,y_{\le t}\) 的期望回报，用于 GAE 优势计算
    Reference（参考基线） \(\pi_{\text{ref}}\) SFT 模型的冻结副本，全程不更新；用于 KL 锚定，约束策略不要偏离原始分布
    Reward Model \(R_\psi(x,y)\) 冻结，对完整回答 \(y\) 输出一个标量偏好奖励，仅在序列末尾生效

    注意区分：\(\pi_{\theta_{\text{old}}}\) 是本次 rollout 采样时冻结的 Actor 版本（PPO 经典旧策略）；\(\pi_{\text{ref}}\) 是固定 SFT，二者不是同一个东西。

    1.3.2 Token 级奖励构造（RLHF 最关键）¶

    奖励模型只在序列最后一步给出稀疏标量奖励；我们在每一个生成 token 上，加入对参考模型的 KL 惩罚，把稀疏奖励转化为稠密逐 token 奖励：

    \[ r_t = -\beta \log \frac{\pi_\theta(y_t\mid x,y_{<t})}{\pi_{\text{ref}}(y_t\mid x,y_{<t})} + \mathbb{1}[t=T]\cdot R_\psi(x,y) \]
    • \(\mathbb{1}[t=T]\)：指示函数，只有序列结束时刻 \(t=T\) 才加上 RM 的偏好奖励；其余时刻只有 KL 惩罚项
    • 含义：每一步都有稠密的 KL 塑形信号，任务偏好奖励只在终止位置稀疏出现
    • 在这一串 token 级奖励序列上，运行 GAE，计算逐 token 优势 \(\hat A_t\)，送入 PPO-Clip 目标

    PPO 的 token 级重要性比率： $$ r_t(\theta) = \frac{\pi_\theta(y_t\mid x,y_{<t})}{\pi_{\theta_{\text{old}}}(y_t\mid x,y_{<t})} $$

    KL 惩罚在 RLHF 中承担双重角色： 1. 作为信任域约束，限制新策略和SFT参考模型之间分布偏移； 2. 抑制奖励黑客（reward hacking）：没有KL锚定，策略很容易找到奖励模型的漏洞，生成RM高分但人类不认可的低质量文本。

    PPO-PTX 混合目标（解决对齐税）¶

    只优化 PPO 奖励，模型容易丢失原始语言能力、世界知识、编码能力（对齐税 / 模型退化）。 InstructGPT引入预训练正则项：在PPO目标上叠加预训练数据的语言建模损失 $$ J_{\text{total}} = J_{\text{PPO}} + \lambda_{\text{ptx}} J_{\text{pretrain}} $$ \(J_{\text{pretrain}}\)：在一部分无标注预训练文本上，最大化原始基座的对数似然；\(\lambda_{\text{ptx}}\) 控制强度。

    这个就是上一篇提到的 PPO-ptx，是早期 RLHF 必不可少的组件。

    RLHF-PPO 完整流水线步骤 ¶

    1. 采样阶段：冻结旧策略 \(\pi_{\theta_{\text{old}}}\)，输入一批 prompt，自回归生成回答，收集 rollout
    2. 打分：RM 给出序列末尾原始奖励，按上面公式计算每个 token 位置带 KL 惩罚的稠密奖励 \(r_t\)
    3. 计算 GAE 优势 \(\hat A_t\)
    4. 在这批 rollout 上跑多个 epoch 的 PPO 更新（clip 目标 + value loss + 可选熵奖励 + ptx loss）
    5. 更新 Actor 参数，更新完成后，把 \(\pi_{\theta_{\text{old}}}\) 设置为当前新策略，进入下一轮 rollout

    2. RLHF 里几个关键概念 ¶

    2.1 奖励黑客 Reward Hacking ¶

    RM 是一个拟合人类偏好的近似模型，不是完美人类。LLM 会找到 RM 的漏洞，生成RM 高分、但人类不认可的回答： - 例子：重复关键词、过度礼貌、空洞废话，专门哄RM打分高 - 缓解手段： - 逐token KL约束（最基础） - 更小的PPO \(\epsilon\)（大模型RLHF一般0.1） - 更好、更多样的偏好数据 - 后续算法：RLAIF、DPO（直接抛弃RM，避开奖励黑客）

    2.2 对齐税 Alignment Tax ¶

    经过 RLHF 之后，模型在对话、遵循指令上更好，但在推理、代码、知识问答上性能下降，这个性能损失叫对齐税。 原因：PPO只优化人类偏好奖励，会偏离基座学到的原始分布。 缓解：PTX loss、控制KL系数不要太大、更好的对齐算法。

    2.3 为什么生成式 LLM 是长序列 MDP ¶

    • MDP 状态：prompt + 已经生成的 token 上下文 \(y_{<t}\)
    • 动作：下一个 token \(y_t\)
    • 每一步动作之后，状态转移（把新 token 拼进上下文）
    • 原始偏好奖励只在序列结束才拿到（稀疏奖励） → 所以必须GAE，把末尾的终局奖励回溯分配到前面每个token，估计每个位置的优势，这是RLHF训练稳定的核心。

    2.4 普通 PPO vs RLHF-PPO ¶

    • 普通 PPO：环境实时返回每一步奖励，环境是固定模拟器；约束主要来自 clip
    • RLHF-PPO：没有外部环境，奖励来自固定神经网络 RM；奖励天然稀疏，靠 KL 惩罚构造稠密 token 奖励；存在两层约束：PPO clip（约束 \(\pi_\theta\) 和 \(\pi_{\theta_{\text{old}}}\)）+ KL 锚定（约束 \(\pi_\theta\) 和冻结 SFT 参考 \(\pi_{\text{ref}}\)）；通常加上 ptx 正则

    数学内核一样，但是 MDP 结构、奖励来源、约束目标完全不一样。

    3. RLHF 的优缺点 ¶

    ✅ 优点 1. 可以从偏好学习，不需要给每个样本写精确奖励函数，适配人类主观评价 2. 基于PPO，工程成熟，是第一代大模型对齐范式（InstructGPT、GPT-3.5早期对齐都用这套） 3. 逐token KL + clip双重约束，对齐之后模型更贴合人类意图，减少有害输出、拒绝越界请求

    ❌ 缺点 1. 流水线长，三阶段训练，成本极高：SFT、RM、PPO三套训练 2. 奖励黑客问题，RM带来偏见、漏洞 3. PPO训练不稳定，超参敏感（KL系数、epsilon、GAE lambda、ptx权重很难调） 4. 样本效率低，rollout生成代价巨大 5. 存在对齐税，容易损害原始能力

    4. RLHF 后续演进（前沿方向，引出下一章 DPO）¶

    RLHF 需要 RM + PPO 两套模型，训练复杂、不稳定。后续提出直接偏好优化 DPO： - 抛弃显式奖励模型，直接用偏好数据优化策略，不需要单独训 RM、不需要 PPO - 把偏好约束转化为策略之间的对数比率损失，等价于隐式的奖励优化 - 训练更简单、稳定、成本更低，现在已经成为主流对齐方案

    还有其他分支： - RLAIF：用AI反馈替代人类标注，AI生成偏好对，减少人工成本 - KTO、IPO：其他偏好优化变体 - ORPO：把SFT和偏好对齐合并到一个阶段

    一句话总结演进：RLHF = SFT + RM + PPO；DPO 干掉 RM 和 PPO，一步到位做偏好对齐。

    5. RLHF 整体公式汇总 ¶

    1. SFT 目标 $$ \mathcal{L}{\text{SFT}} = -\log \pi(y|x) $$}
    2. RM pairwise 损失 $$ \mathcal{L}{\text{RM}} = -\log\sigma\big(R\psi(x,y_l)-R_\psi(x,y_w)\big) $$
    3. Token 级奖励（RLHF 核心） $$ r_t = -\beta \log \frac{\pi_\theta(y_t\mid x,y_{<t})}{\pi_{\text{ref}}(y_t\mid x,y_{<t})} + \mathbb{1}[t=T]\cdot R_\psi(x,y) $$
    4. PPO clip 目标 $$ J^{\text{PPO}} = \mathbb{E}\left[\min\left(r_t(\theta)\hat A_t,\; \text{clip}(r_t(\theta),1-\epsilon,1+\epsilon)\hat A_t\right)\right] $$ $$ r_t(\theta)=\frac{\pi_\theta(y_t\mid x,y_{<t})}{\pi_{\theta_{\text{old}}}(y_t\mid x,y_{<t})} $$
    5. PPO-PTX 总目标 $$ J_{\text{total}} = J_{\text{PPO}} + \lambda_{\text{ptx}} J_{\text{pretrain}} $$

    4. PPO 在 LLM RLHF 中的映射 ¶

    PPO 之所以成为 LLM 对齐的主力，是因为它的 Clip 目标可以逐 token 地施加信任区域，而不需要对整个序列的概率做复杂的约束设计。

    四个模型：

    角色 符号 作用
    Actor（策略） \(\pi_\theta(y_t\mid x,y_{<t})\) 被训练的语言模型，执行生成
    Critic（价值） \(V_\phi(x,y_{\le t})\) 同一 backbone + 标量头，估计每个前缀的期望回报
    Reference（参考） \(\pi_{\text{ref}}\) SFT 模型的冻结副本，用于 KL 锚定
    Reward Model \(R_\psi(x,y)\) 对完整回复给出标量奖励

    Token 级奖励的构造：

    奖励模型只在序列末尾给一个标量 \(R_\psi(x,y)\)；在每一个生成 token 上，加入对 reference 的 KL 惩罚：

    $$
r_t
=
-\beta \log \frac{\pi_\theta(y_t\mid x,y_{<t})}{\pi_{\text{ref}}(y_t\mid x,y_{<t})}
+
\mathbb{1}[t=T]\cdot R_\psi(x,y).
$$

    这意味着每一步都有稠密的 KL 塑形信号，任务奖励只在终止位置稀疏出现。然后在这个 token 级奖励序列上计算 GAE，得到逐 token 优势 \(\hat A_t\)，再代入 PPO-Clip 目标。token 级概率比为：

    \[ r_t(\theta) = \frac{\pi_\theta(y_t\mid x,y_{<t})}{\pi_{\theta_{\text{old}}}(y_t\mid x,y_{<t})}. \]

    KL 惩罚在 RLHF 中承担双重角色：它既是 PPO 信任区域的实现方式，也是防止 reward hacking 的核心机制——没有 KL 锚定，策略会找到奖励模型的盲区，生成高奖励但质量低下的文本。
